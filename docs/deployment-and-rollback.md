# 部署与回滚

本地 Docker 为验收目标。首次 `docker compose up --build -d` 自动初始化 MySQL。`docker compose ps` 检查健康，`docker compose run --rm smoke` 检查业务闭环。首次拉取需要网络，已有卷不会重跑 seed。

更新前：记录当前源码 / 镜像版本，暂停新任务并等待已有任务终态，备份数据库及 files 卷到独立安全位置。MySQL 可通过容器内 mysqldump 导出；文件卷用临时工具容器只读挂载后归档。备份前确认没有制作进行中，保证数据库结果路径和文件一致。

升级：保留卷，构建新镜像，`docker compose up -d`，健康后做一次成功和一次失败任务。修改数据库时使用显式可审查 SQL，已有卷不会应用新初始化脚本。

回滚：切回上一份源码 / 已记录镜像并重新 up，复核健康、个人历史和结果。若 schema 或身份摘要方案不兼容，先停应用并恢复成对的 MySQL / 文件备份，再启动旧版本。不要仅回滚代码后假定数据库兼容。

`docker compose down` 保留卷；`down -v` 只用于明确可清空的测试项目。当前运行中任务不支持服务重启后自动续跑，所以应在任务终态后升级。禁止把刷新恢复视作重启恢复。
